# Pulse 0.1 Enterprise MVP release notes

Pulse 0.1 establishes the first production deployment boundary and leaves the development/source database untouched while moving operational setup away from development tooling. Release acceptance requires the supported imports and reconciliation to preserve every in-scope financial, relational, price-history, revision, and document record; the summary-only quote CSV is not sufficient when the accepted source contains BOM, revision, or document data.

## Security

- Removed automatic production demo/default-user creation and all hard-coded seed passwords.
- Added a protected browser-based first-run Administrator setup for a clean database, plus maintenance-only recovery/rotation and credential-free audit provenance. The setup code closes permanently after the first transaction.
- Replaced signed in-memory-style cookies with opaque, HMAC-digested database sessions; secure/HTTP-only/strict cookies, idle/absolute expiry, login rotation, logout invalidation, and session-bound CSRF are enforced.
- Added persistent username and pseudonymous-IP throttles, temporary lockout, cooldown recovery, generic failures, fake password verification, and redacted security events.
- Production startup validates strong independent secrets, HTTPS, exact proxy hops, restricted database identity, reference data, no demo users, and safe setup/account provenance. An empty installation starts only with a strong one-time setup code.

## Runtime and recovery

- Added separate development, immutable production, maintenance/backup, and isolated CI Compose configurations.
- Production uses compiled API/Next servers, read-only non-root containers, health checks, restart policies, internal application/data networks, named data volumes, and gateway-only host ports.
- Added restricted PostgreSQL runtime/migration roles and declarative MinIO application policy.
- Added encrypted, timestamped PostgreSQL/MinIO/config backups and isolated new-volume restoration with manifests/checksums and deep document reconciliation.
- Made the ClamAV production platform explicit and configurable so the supported upstream image builds predictably on ARM and x86 operator hosts.

## Database and data quality

- Established the validated pre-0.1 Prisma baseline and a controlled adoption workflow; production no longer uses `prisma db push`.
- Enterprise migration adds authentication/maintenance/lifecycle-disposition metadata and conditionally removes only the proven-obsolete request FK and redundant unique index.
- Site creation is never implicit. New interactive clients/requests/quotes require the relevant real site/contact/assignee; incomplete imported legacy records are preserved and reported.
- Added default-preview reports and digest-gated, idempotent maintenance for known anomalies, lifecycle duplicates, and legacy checklist adoption.
- Historical analytics validates event chains, excludes reviewed duplicate/superseded events, falls back to current status only where appropriate, and flags unreliable historical intervals.

## First-run data load

- Pulse 0.1 uses a new release database rather than promoting the current development database.
- First-run setup creates the only initial Administrator and the built-in role definitions, then sends the Administrator to user provisioning.
- The Import page now guides operators through clients, items, and legacy quote summaries in dependency order.
- All three importers use exact CSV templates, preview-first row classification, digest/timestamp revalidation, explicit selection, atomic apply, idempotent matching, and credential-free batch provenance.
- Item imports create initial price-history records and append history on cost or sell-price changes.
- The reviewed 443-row client file passes application validation with zero invalid rows and proposes no site creation.

## Compatibility

- `RequestUpdate` is the canonical request timeline. Legacy activity/task/note reads adapt to it and new legacy writes are disabled.
- Checklist instances are canonical; legacy checklist items remain readable and can be adopted without deletion after a reviewed preview.
- `/importers/clients/*` is the canonical import implementation. `/clients/bulk/*` remains temporarily as a deprecated delegating adapter, not a second business-logic path.

## Accepted limitations

- Ambiguous lifecycle history is flagged, not fabricated.
- Historical missing sites, contacts, and assignees require human stewardship; Pulse creates none automatically.
- Legacy tables/routes remain during the compatibility period.
- Large service modules and the global stylesheet remain post-release refactoring work.
- Production data repair and compatibility adoption require a separate operator-reviewed change; the release does not auto-apply them.
- The verified live lifecycle collisions are not payload-identical and are intentionally left untouched; 29 coexisting checklist rows also remain deferred because 13 contain conflicting historical state.
- The 0.1 quote CSV is a legacy quote-summary importer. Pulse BOM lines, revision files, and document objects require a separate reviewed import path if they are part of the accepted release source.
