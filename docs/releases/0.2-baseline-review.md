## Architecture and existing scope

The documented boundary matches the inspected source:
Browser → Caddy → Next.js → NestJS → PostgreSQL / MinIO / ClamAV.
Next.js proxies `/api` to NestJS. NestJS owns business rules and persistence;
shared contracts must remain independent of either application.

| Area | Current implementation / starting points |
| --- | --- |
| Browser | Next.js 16 / React 19; `apps/web/src/app`, feature modules, shared components and browser API clients |
| API | NestJS 11; `apps/api/src/app.module.ts`, controllers and domain modules |
| Contracts | Zod schemas and payload types under `packages/contracts/src`; quote contracts span `work.ts` and `items.ts` |
| Database | Prisma 7; sole schema at `apps/api/prisma/schema.prisma`; seven active forward migrations through `202608070001_project_quote_change_orders` |
| Quote workspace | `apps/web/src/modules/quotes/QuoteWorkspace.tsx`; Work, Details, Files, Updates, revision viewing and lifecycle actions |
| Quote orchestration | `apps/api/src/lib/services/workService.ts`; thin NestJS quote/item/proposal service wrappers call this shared implementation |
| Financial calculations | `apps/api/src/modules/quotes/quote-financials.ts`; Decimal calculations, PULSE line totals and LEGACY summaries, tax excluded from profit and project budget |
| BOM/catalog | Catalog and ad hoc lines, products/labor/services, quantity/cost/price/discount, kit expansion, required/optional related items, default labor and price history |
| Lifecycle | Audited mark-sent and financial locking, Administrator undo, revision snapshots, original-quote approval/project creation and change orders |
| Projects | Approved quote snapshots, reciprocal quote/project links, expenses and financial meters introduced in 0.1.2 |
| Documents | Existing upload, preview/download, MinIO storage and ClamAV inspection; document infrastructure is not a proposal generator |
| Production | Separate development, production, maintenance, release and CI Compose files; Windows installer and tag-driven release workflow |

### Proposal gap

`PATCH /quotes/:quoteId/proposal` currently saves only `proposalNotes` and
`proposalPreparedAt`, plus activity history. The UI explicitly says that
proposal package, review and export features are future work. Revision JSON
captures these notes, but no dedicated generated-proposal model, template
renderer, PDF generation pipeline or customer delivery workflow was found in
the inspected source. Mark-sent records a lifecycle action; it does not send
the proposal to a customer.

The 0.2 specification should distinguish extending the existing quote builder
from implementing the customer-facing proposal output. Existing financial,
revision, document and project handoff behavior forms the compatibility baseline.

One financial detail needs explicit scope review: `calculateQuoteLine` accepts
an optional tax amount, but the current BOM create/update paths call it without
that amount, defaulting line tax to zero. The presence of a `taxable` field does
not establish an implemented tax-rate policy.

### Proposed consolidation sequence

1. Use `cb8c92d` / `v0.1.2` as the baseline and create `release/0.2.0` from it.
2. Port the applicable installer code and tests in a focused change, retaining
   the released migration history and validating upgrade compatibility.
3. Bring `master` forward to include the released 0.1.2 work through the normal
   repository integration process; do not rewrite published release history.
4. Extend `.github/workflows/ci.yml`: it currently triggers pushes only on
   `main`/`master`, and PRs only when targeting `main`/`master`/`develop`.
   Pushes or PRs targeting `release/0.2.0` are not automatically covered.
5. Map the incoming scope document to contracts, schema, API, quote UI,
   generated documents, regression checks and upgrade acceptance criteria.
6. Consider deleting redundant branches only after consolidation is recorded.

No branch was created, merged, deleted or pushed during this review.

## Documentation assessment

Reviewed the root and application READMEs and the architecture, quote builder,
responsive, release, production and technical-debt documentation. Relative
file-link checks across all 20 tracked Markdown files found no missing targets
(heading anchors and external links were not checked).

- Architecture and ownership rules agree with the current workspace layout.
- `docs/releases/0.1.2.md` and its JSON upgrade contract describe the latest
  tagged source. The older readiness report is dated 2026-07-22 and applies to
  the 0.1.0 candidate; its test counts, database findings and GO decision must
  not be presented as current 0.2 evidence.
- Production runbooks contain initial-0.1 installation instructions, historical
  data observations and a named stale container. These are historical context,
  not instructions to recreate an existing installation or remove a container
  without rechecking it.
- The technical-debt register's existing “Pulse 0.2 priorities” is an older
  maintenance backlog. Reconcile it with the owner's quoting/proposal scope;
  it does not define the new marathon by itself.
- `docs/quote-builder-v0.1.md` remains useful for financial invariants but does
  not specify proposal generation or fully document the newer change-order flow.
- Large implementation files are relevant to planning: `workService.ts` has
  3,761 lines, `QuoteWorkspace.tsx` 1,752, and global CSS 25,537. Prefer focused
  domain extraction as required by the scope, with behavior-preserving checks.
