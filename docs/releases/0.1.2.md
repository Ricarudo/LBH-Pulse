# Pulse 0.1.2 release notes

Pulse 0.1.2 is the corrected Windows update for Pulse 0.1.0 and 0.1.1 installations. It contains the full Pulse 0.1.1 application and schema changes while preserving the fixed Pulse AppId, protected configuration, Compose project, and existing PostgreSQL and MinIO volumes.

## Windows updater correction

- Makes migration-ledger verification resilient to unrelated Docker Compose and Windows PowerShell stderr output while continuing to require the exact expected successful migration rows.
- Writes a sanitized `installer-error.txt` and explicit installer log entry when update preparation fails.
- Accepts the four-migration Pulse 0.1.0 ledger and the cumulative six-migration Pulse 0.1.1 ledger as version-appropriate source states.
- Keeps ledger validation, encrypted pre-update backup, digest-pinned images, restricted migrations, and post-update health checks mandatory.

The 0.1.1 installer could incorrectly reject a valid 0.1.0 ledger before creating a backup or changing the running deployment. A machine affected by that failure can run the 0.1.2 installer directly; it reads the protected installer state rather than relying on the Apps & Features display version.

## Database update

When updating from Pulse 0.1.0, the normal installer applies the two additive migrations introduced by 0.1.1:

1. `202608030001_quote_due_date`
2. `202608030002_lifecycle_collaborators`

When updating from a completed Pulse 0.1.1 installation, those migrations are verified and are not reapplied. The updater never runs `prisma db push`, `prisma migrate reset`, or a destructive down migration.

## Signing and integrity

Use `Pulse-Setup-0.1.2.exe` and its `.sha256` file attached to the `v0.1.2` GitHub release. Prefer an Authenticode-signed installer. If the release is unsigned, verify its SHA-256 through an independently trusted channel before running it as Administrator.
