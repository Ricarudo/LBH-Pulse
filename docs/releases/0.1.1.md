# Pulse 0.1.1 release notes

Pulse 0.1.1 is the supported patch update for an installed Pulse 0.1.0 system. The Windows installer keeps the fixed Pulse AppId, protected configuration, Compose project, and existing PostgreSQL and MinIO volumes. It creates and verifies an encrypted pre-update backup before stopping application writes or applying migrations.

## Fixes and workflow improvements

- Surfaces temporary authentication lockouts to the login experience and clears persisted lockout buckets when an administrator resets a password.
- Fixes quote editing and document preview/download behavior while improving error handling for document requests.
- Expands the quote workspace with editable details, a clearly labeled Send by preparation deadline, collaboration, lifecycle updates, and a clearer dashboard workflow.
- Corrects dashboard date coverage across requests, quotes, projects, and invoices, with deduplicated lifecycle next steps and distinct due-date and next-step indicators.
- Treats marking a quote as sent as an audited lifecycle event, removes its Send by preparation deadline from dashboard analysis, locks the sent financial values, and provides an Administrator-only audited undo for incorrectly recorded delivery.
- Carries collaborators across the shared lifecycle context so related requests, quotes, projects, and invoices can present one consistent collaboration model.
- Improves quick client creation by collecting the real client site required by downstream request and quote workflows.
- Improves item selection and quote-line workflows, including the supporting API contracts and validation coverage.

## Database update

The normal installer update runs `prisma migrate deploy` with the restricted migration identity. It applies two additive forward migrations after the four migrations shipped in 0.1.0:

1. `202608030001_quote_due_date` adds the nullable `Quote.dueDate` column and its index.
2. `202608030002_lifecycle_collaborators` creates the lifecycle collaborator table and copies existing request collaborators into their shared lifecycle context without deleting the source rows.

The update never runs `prisma db push`, `prisma migrate reset`, or a destructive down migration. If migration execution begins and the update later fails, automatic application downgrade remains prohibited; keep writes stopped and restore the verified pre-update archive into new isolated volumes.

## Supported Windows upgrade

- Supported source release: Pulse 0.1.0 (`v0.1.0`, commit `31996fa48af6c54841b9fcb355138528f12b2277`).
- Target release: Pulse 0.1.1.
- Installer AppId: unchanged from 0.1.0.
- Compose project: `pulse-production`.
- Default persistent volumes: `pulse-production-postgres` and `pulse-production-minio`.

Before the update, escrow the installed recovery identity and retain the verified encrypted backup outside the Pulse machine. After installation, verify Administrator login, a representative client/request/quote workflow, quote details and Send by dates, collaborator visibility, and document upload/download.

## Signing and integrity

Use the installer and `.sha256` file attached to the `v0.1.1` GitHub release, not the source archives. Prefer an Authenticode-signed installer. If the release is unsigned, verify its SHA-256 through an independently trusted channel before running it as Administrator.
